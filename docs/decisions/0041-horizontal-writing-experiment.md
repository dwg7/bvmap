# 0041: 縦書き注記の全面横書き化(実験、bvmap-starlightのみ)

[0004](0004-vertical-choonpu-workaround-does-not-work.md)で「MapLibre本体のvert字形対応待ち」として
目標から外した縦書き棒音符問題を、「縦書き自体をやめる」方向で回避する実験(藤村さんの発案)。

## 事実(実データ)

- `bvmap-dark.json`の縦書き注記は、`bvmap-注記シンボルなし縦ソート順100以上/未満`の2層。同じ`Anno`
  ソースレイヤーを参照する横書き層と**`text-writing-mode`以外のlayoutが完全に同一**で、振り分けは
  フィルタの`vt_arrng`(2,4=縦、1,3または無し=横)のみ。文字列は`vt_text`で、縦横の情報は
  タイルの文字列自体には含まれない——縦書きは純粋にstyle側の表示指定。
- 実タイル16枚(z14・15、都市・地方8地点、`stars.optgeo.org/bvmap`を`mapbox_vector_tile`で復号)で
  注記1,708件中、縦書き156件(約9%)、うち「ー」を含む9件(バスセンター前駅・市民センター等)、
  全角括弧・中黒等を含む57件(「一番町（三）」型の丁目表記)。文字の有無の集計で、崩れ方の確認ではない。
- `注記角度付き線`(`["horizontal","vertical"]`)は、z14〜17の都市タイルでLineString注記が0件
  (Pointのみ)で、ほぼ発火しない。今回は触っていない。

## 実装

`starlight-input.yaml`に`layout_overrides:`(id指定のlayout上書き)を新設し、`assemble.py`が
最後に適用する。縦2層の`text-writing-mode`を`["horizontal"]`にした。層数・id・順序は不変
(構造ゲートPASS)、`bvmap-dark.json`は無加工のまま。比較は`examples/style-preview.html`の
ボタン切り替えで行える。

## 確認

札幌バスセンター前: 「バスセンター前駅」が横書きで「ー」が正しい長音の横棒になる(dark版は縦書きで
崩れる)。白馬の山間部(山名・大雪渓等)も横書きになり重なりは目視で無し。

## 密集地での確認(2026-10-06)

6地点(名古屋上前津・東京八重洲/内神田・大阪中之島・仙台一番町・札幌北一条東・福岡天神、z15)で、
dark/starlightを切り替えて`queryRenderedFeatures`で衝突処理後に実際に配置された注記数を比較:
縦2層+横2層の合計がdark 134件→starlight 132件(各地点の差は±3以内)。横書き化で注記が
大きく脱落することは無い。MapLibreは既定で注記同士の衝突を避けるため、注記同士の重なりも
起きない。名古屋大須(z16)・大阪中之島(z15)を目視し、「大須（二）」「北浜（四）」等の丁目表記は
横書きで読め、他の注記と重ならない。線上の注記(`注記角度付き線`)は大阪中之島でも0件で、
やはりほぼ発火しない。残る懸念は注記と地図要素(建物・道路)の重なりだが、これはdarkの
縦書きでも同様で、横書き化で悪化した様子は見られなかった。

## 未決・今後

- 本番(`hfu/stars`)へ出すか: 重なりの懸念は上記の確認で解消。残るのは縦書き慣習(地形図図式の縦書き)を捨てる文化的コストの判断は藤村さん。
- 選択的に(崩れる文字を含む注記だけ)横にする案は、`text-writing-mode`がデータ駆動でない
  (未検証)場合は層分割が必要で、層ID・順序の構造ゲートに手を入れることになる。
