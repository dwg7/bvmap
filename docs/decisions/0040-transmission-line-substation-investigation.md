# 0040: 送電線が変電所を「取り囲む」ように見える件の調査(スタイル側の修正余地なし)

藤村さんから、`localhost:8765/examples/style-preview.html#18.03/35.65256/139.345192`で
送電線が変電所の周りを回っているように見える、スタイルの誤りではないかとの指摘があった。
GSI公式データ・公式コード表・GSI自身の描画と突き合わせて調査した。

## 確認した事実

1. **`bvmap-送電線`/`bvmap-送電線破線`は両方とも`filter: None`**(`style/bvmap-dark.json`で確認)。
   `paint`もvt_codeによる条件分岐を一切持たない単色(`rgba(100,100,100,1)`)。つまりこの2層は
   ソースレイヤー`PwrTrnsmL`の地物を無条件に全て描画しているだけで、vt_codeに基づいて
   「これは変電所だから描かない」という判定をする仕組みがそもそも存在しない。
2. **GSI公式の地物コード表(`optbv_featurecodes.pdf`)を確認したところ、`PwrTrnsmL`ソース
   レイヤーには`vt_code 8202`=「送電線」の1コードしか存在しない**。「変電所」に相当する
   コードは`optimal_bvmap`のデータモデル自体に無い。
3. 該当地点でレンダリングされている地物は実際に`vt_code: 8202`(送電線)で、GSI公式の
   電子国土Web(`maps.gsi.go.jp`、同じ基盤データを使用)でも同じ地点を確認したところ、
   複数本の送電線が同様に建物付近を通る描画になっていた——「ループ」というより、複数の
   送電線が変電所へ収束している実際の地物配置として自然な見え方だった。

## 結論

**スタイル側に修正の余地は無い**。`bvmap-送電線`/`bvmap-送電線破線`は元々vt_codeで
場合分けする設計になっておらず(0022/0025で「単色・一回性装飾、共有化する理由なし」と
判断済み)、`optimal_bvmap`のデータモデル自体が「変電所」を区別するコードを持たないため、
スタイル側でこれを検出して除外・別描画することはできない。見た目の印象(送電線が変電所を
囲んでいるように見える)は、複数の送電線が実際に変電所へ収束しているという地物の実態を
反映したものであり、GSI公式の描画でも同様の見え方になることを確認済み。

対応が必要になるとすれば、`optimal_bvmap`に無い変電所ポリゴン/シンボルを外部データ
(例えば基盤地図情報の建築物/施設ポイントデータ)から別途持ち込む必要があり、現在の
「`bvmap-dark`の構造をそのまま継承し配色だけ磨く」というStarlightの方針([0005](0005-goal-change-master-repo-and-starlight-polish.md))の範囲を超える。
