# 0025: tierブロック後の残り13層、踏み跡調査

[0022](0022-zl4-10-and-post-tier-layers-footprint.md)で洗い出した④(軌道2層の非対称性)を含む、残り13層の踏み跡調査。GSI公式地物コード表(`https://maps.gsi.go.jp/help/pdf/vector/optbv_featurecodes.pdf`)を実際に取得・確認して裏取りした。

## 軌道2層の「非対称性」、完全に解決した

[0022](0022-zl4-10-and-post-tier-layers-footprint.md)では「暗い色になるvt_codeサブセットが両者で微妙に非対称、法則性は未解明」としていたが、GSI地物コード表を確認したところ**きれいに説明できる**ことが分かった。

`RailTrCL`(軌道の中心線)のvt_codeは「種別2桁+状態1桁」の3桁構造:

```
種別: 01=普通鉄道、11=特殊鉄道、21=索道、31=路面の鉄道、41=側線
状態: 1=通常部、2=遮蔽、3=橋・高架、4=トンネル、6=運休中
```

つまり`2801`=普通鉄道の通常部、`2802`=普通鉄道の遮蔽、`2804`=普通鉄道のトンネル、という具合。`bvmap-軌道の中心線`のfilter(17コード: `2801,2803,2806,2811,2813,2816,2821,2823,2826,2831,2833,2836,2841,2843,2846,2888,2899`)は、**各種別の「通常部(1)・橋高架(3)・運休中(6)」の状態だけ**を集めたもの。`bvmap-軌道の中心線トンネル`はその補集合、つまり**「遮蔽(2)・トンネル(4)」の状態**——「遮蔽」(雪覆い等の被覆区間)を「トンネル」層に含めているのは、どちらも「上から見えない区間」という描画上の扱いが同じだからだと読める。

色分けの「暗い(gray30)」対象は、**両層とも種別01(普通鉄道)・11(特殊鉄道)・31(路面の鉄道)の3種別のみ**で完全に一致しており(表層側: `2801,2803,2806,2811,2813,2816,2831,2833,2836`、トンネル側: `2802,2804,2812,2814,2832,2834`)、種別21(索道)・41(側線)は表層・トンネルどちらでも常にdefault(gray100)。**非対称に見えたのは状態(通常部/橋高架/運休中 vs 遮蔽/トンネル)の違いだけで、種別による色分けの論理自体は表層・トンネルで完全に一致している**——「非対称」という当初の見立ては、パーティションの軸を誤認していたための錯覚だった。

## 「共有テーブル+疎な例外」イディオムの3例目・4例目

[0008](0008-cartographic-layer-ordering.md)で確認した「大きな共有テーブルを複数レイヤーにコピーする」というGSIの制作イディオムが、ここでも2つ見つかった:

1. **鉄道の幅係数テーブル**: `bvmap-鉄道中心線地下トンネル`(トンネル本体)のline-widthに埋め込まれた`match(vt_rtcode: JR→600,JR以外→600,地下鉄→500,路面→400,索道→400,特殊鉄道→300,側線→300,0)`は、tierの`bvmap-鉄道中心線0`のline-widthに埋め込まれた同じmatch式と**数値まで完全に一致**する。トンネル側はこれに「駅部分なら+800」という加算項が追加されている点が疎な例外
2. **道路の幅員ランプ**: `bvmap-道路中心線階段`のline-widthに埋め込まれた`vt_rnkwidth`ランプ(300/450/900/1800/2700)は、tierの`bvmap-道路中心線色0`のline-width計算に埋め込まれた同じランプと**数値まで完全に一致**する

## vt_code構造の確認: 道路の徒歩道・石段

GSI表で確認: `27xx`台は種別2桁+状態1桁で、種別21=徒歩道(状態21=通常部/22=雪覆い/23=橋高架/24=トンネル)、種別31=石段(状態31=通常部/32=雪覆い/33=橋高架/34=トンネル)。

- `bvmap-道路中心線階段`は`[2731,2732,2733,2734]`(石段の全状態)を描く——名前通り「石段」専用レイヤー
- `bvmap-道路中心線破線`は`[2724,2734]`(徒歩道トンネル+石段トンネル)だけを対象にした、破線による「トンネル区間」の追加装飾——単独の道路種別ではなく、**「トンネル状態」という横断的な条件**で発火する装飾レイヤーだった

## その他の10層: 単純な一回性装飾、追加の構造なし

- `bvmap-道路縁`/`bvmap-道路構成線トンネル内の道路`/`bvmap-道路構成線分離帯`: z17限定、単色gray100、他レイヤーと共有するテーブルなし
- `bvmap-送電線`/`bvmap-送電線破線`: 単色gray100
- `bvmap-特定地区界`: 既存の理解(地図記号に近い、低存在感)通り、単色・破線・ズームフェード
- `bvmap-水部表記線point`: 色を持たないアイコンレイヤー

## 次に検討すべきこと(未着手)

- 鉄道トンネル系(ククリ+本体)・軌道2層は、いずれも`compile_match_expression()`のflat_matchでは表現できない(複数プロパティ・優先順位を伴う、または widthに複雑な式が絡む)——実装するなら道路のZL4-10と同様、専用モジュールが必要になりそうだが、色だけならシンプルなので着手コストは低いかもしれない
- 残りの単純な一回性装飾(道路縁・送電線等)は、[0009](0009-generator-architecture-direction.md)の「逃げ場」原則通りリテラル保持で十分——共有化する理由が見当たらない
