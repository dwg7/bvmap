# 0016: 道路ティア反復ジェネレータ、Stage 1実装完了

[0009](0009-generator-architecture-direction.md)で設計したStage 1(再現優先のジェネレータ)の最初の実装。`generator/tier_template.py`が、道路・鉄道・建物の複合ティア構造(73レイヤー、[0008](0008-cartographic-layer-ordering.md)参照)のうち、テンプレート化対象の70レイヤー(低ズーム概観用3レイヤーを除く)を再生成する。

## 結果

**65/70レイヤーが`bvmap-dark.json`と完全一致**。残り5レイヤーは、GSI自身のtier4(`>=4`のオーバーフロー段)生成過程の不整合を意図的に再現していない(後述)。

## 実装過程で見つかった、当初のADRに無かった追加の事実

### ティア0だけ、ロールの並び順自体が違う(構造的な例外)

[0009](0009-generator-architecture-direction.md)は「ティア0の`line-color`に1つだけ内容面の例外がある」と記録していたが、実装して初めて、**ティア0だけ建物の描画順序自体が違う**ことが判明した:

- ティア0: 道路→鉄道→道路橋→**建物**→鉄道橋、の順(建物が地上インフラと高架インフラの間)
- ティア1〜4: 道路→鉄道→道路橋→鉄道橋→**建物**、の順(建物が最後)

これは[0008](0008-cartographic-layer-ordering.md)が指摘した「建物が地上と高架の間に挟まる、現実の立体構造の反映」という説明を裏付けるが、この配置が**ティア0だけ**であり、ティア1以降には及んでいない、という点は今回初めて判明した。

### ティア4(オーバーフロー段)に、GSI側の生成過程由来と見られる不整合がある

`bvmap-鉄道中心線旗竿4`等5レイヤーの実際のfilterを確認したところ、`vt_lvorder`の比較演算子(`==`→`>=`)だけでなく、**同一レイヤー内の無関係な比較(`vt_rtcode`の`==`判定等)まで`>=`に置換されている**ことが分かった(例: `[">=", ["get","vt_rtcode"], "JR"]`——文字列の等価判定に`>=`を使うのは意味を成さない)。おそらくGSI側のツールが「`==`を全て`>=`に置換する」という粗い変換をtier4生成時に行った際の副作用で、意図した設計ではないと考えられる。

**方針(藤村さんの判断)**: この不整合は一字一句再現しない。本ジェネレータは`vt_lvorder`の比較だけを意味的に正しく置換し、この既知の例外(`KNOWN_TIER4_ANOMALIES`)は文書化した上でスキップする。

## Stage 1の意義

「ジェネレータは計算するのではなく再生する」([0009](0009-generator-architecture-direction.md)関連の議論)という理解通り、今回の実装過程そのものが**新しい踏み跡の発見**につながった。仕組みを実装してみて初めて「ティア0の並び順が違う」という、ADRのテキストだけでは気づけなかった事実が表面化した——コードを書くこと自体が探索の一形態だった。
