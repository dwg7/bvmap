# 0010: 色の意味カテゴリ(ケース・カンファレンスの結論、ケース2)

[0009](0009-generator-architecture-direction.md)で設計した「カテゴリ registry→プロパティ表→`match`式コンパイラ」に実際に流し込む、色の意味カテゴリを確定する。実データで検証済み。

## 確定したカテゴリ

### 1. 道路種別(`vt_rdctg`駆動、`vt_code`ではない)

道路の色は`vt_code`の単純なランプではなく、**`vt_rdctg`**(国道/都道府県道/市区町村道等/高速自動車国道等/その他/不明)という道路種別属性で決まる。`vt_motorway`フラグが立つと種別によらず優先的に上書きされる。

```
vt_motorway == 1        -> gray(157)  # 高速道路相当、種別を問わず優先
vt_rdctg = 国道          -> gray(160)
vt_rdctg = 都道府県道     -> gray(226)
vt_rdctg = 市区町村道等   -> gray(100)
vt_rdctg = 高速自動車国道等 -> gray(157)
vt_rdctg = その他/不明    -> gray(100)
```

さらに一部の橋梁関連`vt_code`(2704, 2714)は上記とは別の分岐に入る(要・別途確認)。

### 2. 建物種別(`vt_code`駆動、塗りと輪郭で構造が異なる)

塗り(`fill-color`)は建物種別ごとに変化するが、輪郭(`line-color`/`line-width`)はマッチした種別なら一律同じ値で、マッチしない種別は非表示になる——「塗りより輪郭を少し濃くする」という単純なペアではなかった。

```
塗り:
  3101 (普通建物)   -> gray(233)
  3102 (堅ろう建物)  -> gray(203)
  3103 (高層建物)   -> gray(152)
  3111 (普通無壁舎)  -> gray(203)
  3112 (堅ろう無壁舎) -> gray(203)
  default        -> 透明

輪郭:
  3101/3102/3103/3111/3112 のいずれか -> gray(164)、幅1
  default                         -> 透明、幅0
```

### 3. 注記(Anno)の重要度ランプ(`vt_code`駆動、7レイヤー共通)

[0008](0008-cartographic-layer-ordering.md)で確認済み。8段階(29/42/50/59/68/70/80/98)が、Anno由来の7つの注記系レイヤーに同一のカテゴリ表として適用される。カテゴリの中身(どの`vt_code`がどの段階か)は、[0009](0009-generator-architecture-direction.md)の「共有テーブル+疎な例外」を前提に、既存の`match`式からそのまま抽出する。

### 4. 汎用色(意味カテゴリに昇格させない)

gray=100(62レイヤーで無関係なカテゴリ横断使用)、gray=255/0(白黒、汎用の地)、gray=209(背景プレースホルダーと水域が偶然同じ値)は、独立した意味を持たないため、カテゴリ registryには昇格させず、「その他・既定値」としてそのまま残す。
